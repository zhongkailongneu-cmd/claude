# 医学机制交互图

本 skill 和 anatomy 搭配使用。anatomy 负责「画得好」：零件、四档明暗、遮挡顺序、动效和验证脚本。本 skill 负责「讲得对」：把机制翻译成一台机器、审查这台机器有没有讲错、让每个数字都有出处，最后套上三种底色和中文文案。

开始之前先读 anatomy 的 SKILL.md。下面凡是写「按 anatomy」的步骤，都照它的规则执行。

## 核心想法：机制就是机器，但比喻要经得起审查

Anatomy 只画机器、仪器、工具和家具，不画人体，也不画精确的解剖图。所以神经、药理、肿瘤学的概念必须先翻译成一台机器，机器本身怎么运转，就是机制怎么运转。例如：

| 概念 | 机器 | 读者看到的运动 |
|---|---|---|
| 突触的量子释放 | 弹匣式定量发射器，钙离子扳机触发 | 每次触发随机射出 0 到 n 发，有时一发不出 |
| 血脑屏障与 P-gp 外排 | 带密封门的过滤闸，加一台耗能的回推泵 | 脂溶的小分子穿门而过，底物被泵推回血液侧 |
| 一室药代动力学 | 带排水阀的量杯水箱，定时加药漏斗 | 液面按指数下降，反复加药后稳态液位升高 |
| CDK4/6 与 G1/S 检查点 | 装配线上的锁扣闸门，Rb 是锁扣 | 抑制剂插入后锁扣打不开，工件停在 G1 |

完整的对照表（12 个机制，每个都写明比喻在哪里失真、该引用什么文献）在 `references/metaphor-map.md`。

比喻是双刃剑。一台好机器能让读者一眼看懂，但它也会悄悄带进一些真实生物学里并不存在的性质：「锁和钥匙」暗示刚性嵌合，「闸门」暗示非开即关，「发射器」暗示每次都会发射。所以每张图都要过一遍映射审计（第 4 步），并在页面上写出「比喻的边界」。读者应该同时带走两样东西：机制是怎么运转的，以及这台机器在哪些地方不像真实情况。

## 与其他 skill 的分工

| 谁负责 | 做什么 |
|---|---|
| anatomy | 零件清单的工艺、几何、上色、遮挡顺序、动效、`lines.mjs` 等验证脚本 |
| 本 skill | 选比喻、审比喻、参数与出处、三种底色、中文文案、科学审读 |
| 文献检索工具（PubMed、Amass、Consensus 等连接器，或网页搜索） | 核对每一条引用的作者、年份、期刊、卷期和页码 |

如果当前环境没有 anatomy，先请用户安装（`npx skills add wheresryan22/anatomy`，或上传 ZIP 到 claude.ai 的 Skills）。在装好之前，只交付第 1–4 步的设计稿：比喻、映射审计表、参数登记表，不要用其他方法凑一张图出来。

## 工作流

按顺序做。前四步决定了这张图讲得对不对，比画得多漂亮更重要。

1. **定问题和读者。** 一张图只回答一个问题，例如「为什么 98% 的小分子药物进不了脑？」。读者是谁（本科生、研究生、临床同行还是患者），决定了术语的密度和数字的精度。规模（Figure、Hero 还是 Epic）按 anatomy 的标准来定，并告诉用户。

2. **先查证，建参数登记表。** 列出图里会出现的每一个数字：读数、刻度、图注、正文里的都算。每个数字登记一条：数值、单位、出处、证据级别，写在 `assets/evidence.mjs` 的 `defineParams` 里。出处要用检索工具核对过，不能凭记忆写卷期页码；查不到原文的标【待核】。只为画面服务、不是实测的数字，证据级别记为 `S`（示意值），页面上也标「示意」。详细规则见 `references/evidence.md`。

3. **选机器。** 先查 `references/metaphor-map.md`。表里没有的，就按下面的「映射五问」自己发明一台。机器要能用一句话说清：什么在动，这个动作代表什么。

4. **映射审计。** 填写映射表：每个机器部件 ↔ 对应的生物学实体 ↔ 保留了哪些性质 ↔ 扭曲或丢失了哪些性质。每一处失真只有三种处理方式：
   - 改设计，让机器把这一点也表现出来（例如让发射器随机哑火）；
   - 写进页面的「比喻的边界」，明确告诉读者；
   - 如果失真会误导核心结论，放弃这个比喻，换一台机器。

   方法、常见的误导性比喻和审读清单，见 `references/fidelity.md`。

5. **零件清单与绘制。** 按 anatomy 的工作流第 4–9 步来做。唯一一个高亮（lit）的部件，应该是读者要盯着看的那个东西：药物、离子、信号或者被锁住的工件。随机过程要画成随机的；读数从同一个模型实时算出。

6. **页面外壳与三种底色。** 用 `assets/surfaces.mjs` 的 `pageDocument()` 代替 anatomy 的 `pageHtml()`，用 `pickerHtml()` 在页面右上角放三个色块。没有选过时，页面跟随系统：浅色对应浅蓝，深色对应深蓝；选过之后会记住选择。用法见下面的「三种底色」一节。

7. **中文文案。** 按 `references/copy-zh.md` 的模板写：标题、卡片四角、图例、图注、「它是怎么工作的」「比喻的边界」「证据与出处」，以及涉及临床时的免责声明。

8. **出处检查。** 构建脚本最后调用 `auditOrExit(PARAMS, SOURCES, { texts })`。它会检查三件事：每个参数都有出处和证据级别、每个出处都被用到、正文里没有来历不明的数字。不通过就修，直到它打印「出处检查通过」。然后再逐条对照 `references/evidence.md` 的人工清单检查一遍。

9. **验证。**
   - 三种底色各构建一次（`--light`、`--navy`、`--black`），每个都按 anatomy 的方法验证：`lines.mjs` 输出 0、手机宽度 390 下截图、看过每一张截图。
   - 再做一遍科学审读：把页面上每一句事实性陈述列出来，每一句都要能指向一条出处，或者明确标为「示意」「简化」。

10. **交付。** 交付三样东西：
    - 页面：独立的 `html` 文件，以及发布为 claude.ai Artifact 用的 `fragment`；
    - 一份简短说明：用了什么机器、比喻的边界有哪几条、出处列表和证据级别；
    - 用户需要自己核对的点，比如所有【待核】的引用，以及示意值是否应该换成某个具体药物的真实数据。

## 映射五问（选机器、审机器都用这五问）

1. **动的东西对得上吗？** 机器里每个运动部件，都要对应一个真实在变化的量。没有对应物的运动只是装饰，要删掉。
2. **数量和比例对得上吗？** 至少要保证数量级正确。如果为了画面把 1:1000 画成了 1:2，要在读数或图注里写出真实比例。
3. **是随机的还是确定的？** 递质释放、通道开关、受体结合都是随机过程，机器也必须表现出随机性：会失败、会波动，读数给出概率或均值。
4. **能量和方向对吗？** 被动扩散（顺浓度梯度、不耗能）和主动转运（耗 ATP 的泵）不能用同一种动力来画。
5. **时间尺度对吗？** 毫秒级和小时级的过程放在同一张图里时，读数显示真实时间；动画可以加速，但要在图注里写明加速了多少倍。

## 三种底色

`assets/surfaces.mjs` 是唯一的颜色来源。它为每种底色定义了全部 `--anatomy-*` 变量，另外补了 4 个 Anatomy 套件里没有的插图变量：`--fig-glass` 和 `--fig-glass-o`（玻璃色和透明度）、`--fig-screen`（屏幕底色）、`--fig-lens`（镜片或观察窗）。

| 色块 | 名称 | `data-surface` | 什么时候用 |
|---|---|---|---|
| ⚪ | 浅蓝 | `light` | 系统浅色时默认；讲课投影、白天阅读 |
| 🔵 | 深蓝 | `navy` | 系统深色时默认；发社交媒体、做封面 |
| ⚫ | 黑色 | `black` | 只在用户选中时；Anatomy 原版风格 |

构建脚本里的用法（`assets/starter-build.mjs` 是一个可以直接运行的完整例子）：

```js
const { pageDocument, pickerHtml } = await import(pathToFileURL(join(ASSETS, "surfaces.mjs")).href);
const { html, fragment } = pageDocument({
  isoCss: k.ISO_CSS, title: "血脑屏障过滤闸",
  body: header /* 里面放 pickerHtml({ corner: true }) */ + figure + sections,
  script: kitScript() + live, css: FIGURE_CSS,
  force: ["light", "navy", "black"].find((n) => process.argv.includes("--" + n)) || null,
  key: "bbb-surface",
});
```

颜色规则：
- 机器的结构、线条、玻璃和屏幕，颜色只用上面这些变量，不要写死色值。
- 浅蓝和深蓝里出现的蓝色，只能用 Loyel 色板的 10 个色值。
- 图里画的内容（染色切片、药片、示意的分子颜色）可以保留自然色，但只在颜色本身就是信息的时候。
- 不要给 `<body>` 加 `class="iso"`，否则 Anatomy 默认的灰色变量会把三种底色覆盖掉。

## 读数与出处

读数会让读者以为「这是真的」，所以每个数字都必须经得起追问。
- 页面上出现的每一个数字，都来自参数登记表里的一项。读数和图注里，数字后面跟上标出处号（¹ ² ³），用 `mark()` 生成；页面底部的「证据与出处」由 `sourcesHtml()` 自动生成。
- 证据级别：A 指南、系统综述或 RCT；B 单项临床研究；C 动物或体外研究；D 教科书或共识；S 示意值。动物或体外研究得出的数字，不能写成「人体如此」。
- 涉及剂量、血药浓度、治疗窗的图，页面上必须放免责声明：这是机制示意，不能替代个体化诊疗，剂量以药品说明书和指南为准。
- 完整的人工检查清单在 `references/evidence.md`，交付前逐条核对。

## 质量红线

- 不画人体、器官或解剖结构。需要的话，在正文里用文字说明，或者链接到解剖图谱。
- 不给出针对个人的用药或剂量建议。
- 随机过程不能画成确定性的（见映射五问第 3 条）。
- 没有出处的数字，不能出现在读数里；示意值必须标「示意」。
- 每张图至少写两条「比喻的边界」。如果一条都写不出来，说明审计做得不够。
- anatomy 的全部工艺规则照样适用：实体而不是线框、只有一个高亮部件、所有线条都要落在东西上、三种底色下都要通过验证。
